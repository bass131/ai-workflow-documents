## 다음에 시작할 주제 · 제안

**「TDD와 완료 검증」의 상태 통제 세부사항을 사용자와 먼저 논의한다.** 전체 흐름에는 핵심과 연결만 두고, 상태 전환·완료 권한·재검증·한도·재개 규칙의 정본은 검증 문서에 둔다.

대상은 [한국어 문서](../src/content/docs/ko/workflow/verification.md)와 [영어 문서](../src/content/docs/workflow/verification.md)다. 문서 보강은 실행기 구현 착수를 뜻하지 않는다.

1. 기존 문서와 「전체 흐름」의 설정 저장 가상 예시를 읽고, 이미 정한 원칙과 미정인 설계를 구분한다.
2. 다음에 다룰 범위를 사용자와 정한다. 후보는 작업 상태와 전환 조건, 검사 결과의 유효성, 완료 권한의 분리, 한도 소진과 재개다.
3. 필요한 기준과 예시를 제안하고 합의 후 반영한다. 특히 RED → GREEN 순서의 프로그램 강제는 합의 없이 확정하지 않는다.
4. 양쪽 언어와 [작성 가이드](authoring.md)의 실제 화면 검토를 따른다. 핵심 흐름은 도표로, 세부 판단은 표와 짧은 예시로 설명하며 중복 설명은 기준 문서에 연결한다.

승인한 범위 밖의 본문을 먼저 수정하지 않는다. 기존 목차에서 한 주제씩 논의하고, 합의한 범위를 적용한다.

## 유지할 합의와 미정인 부분

- **작성 기준:** 일기나 대화 중계가 아닌 위키. 정의·역할·적용 조건·예시·한계를 중심으로 쓰고, 구현·관찰·제안을 구별한다. 기준의 정본은 [작성 가이드](authoring.md)다.
- **단계와 자율성:** 한 목표를 필요한 만큼 1–7개 단계로 나누고 각 단계를 중간 결과와 완료 기준을 가진 마일스톤으로 정의한다. 단계 관리와 맥락 조율은 함께 중요하다. 메인이 목표·진행을 유지하며 구현·검토를 위임하되, 에이전트 수·직렬/병렬·세션 교체는 작업에 맞춰 판단한다. 고정 팀을 요구하지 않는다.
- **검증:** 의미 있는 테스트와 최종 회귀 검사를 유지한다. 실제 완료 관리 프로그램은 제안 단계이며, RED → GREEN 순서를 프로그램으로 강제할지는 미정이다. [검증 문서](../src/content/docs/ko/workflow/verification.md)를 기준으로 논의한다.
- **AgentDeck:** 기존 Claude Agent SDK 유지, Codex 추가 시 App Server 활용, 공통 책임은 목표·검증·재개에 집중하는 방향이다. 리파인 브랜치는 재사용 가능성을 남겨 보류한다. 다음 사이트 작업이 AgentDeck 구현이나 브랜치 정리를 시작할 권한을 뜻하지는 않는다.
